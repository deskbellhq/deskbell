# Documentation site

> Status: done · 2026-08-25

**Goal.** Deskbell has no documentation site. What a self-hoster needs is spread across
`README.md`, three files in `docs/`, the comments in `.env.example`, and specs in `.ai/`
that are written for builders rather than operators. Since the product is installed by
running `docker compose up` and embedding a widget, the install path *is* the
documentation — a missing page is a user who cannot finish. This adds `apps/docs`, a
Fumadocs site served at `/docs` on the marketing domain, covering the whole path from
`docker compose up` to an answering widget.

## Design

### Placement: an app in this repo

`apps/docs` rather than a separate repository. Three reasons, in order of weight:

1. **A doc and the code it describes change in the same commit.** Split across
   repositories they change in two, and the second one is the one that gets forgotten.
2. **The widget reference has a real single source of truth already.**
   `packages/shared/src/widget-config.ts` is read by the widget, the snippet loader, the
   React wrapper, the dashboard editor and the DB schema. The docs site imports the same
   descriptor and renders its tables from it, so there is no generated artifact to check
   and no second copy to forget. Across a repository boundary this would have to become a
   sync job.
3. **"Edit this page" lands a contributor in the repository they already cloned.**

The app is AGPL, like the other apps, and imports MIT `@deskbell/shared`. That direction
is allowed; the reverse is not, so no package under `packages/` gains a Fumadocs
dependency.

### Routing: `basePath: '/docs'`

The docs app builds with `basePath: '/docs'` and the marketing site rewrites
`/docs/:path*` to this deployment. The app keeps its own `vercel.json` and its own
project, so it deploys independently.

Two consequences that are easy to get wrong and are therefore pinned by tests:

- **Pages mount at the app root** (`app/[[...slug]]/page.tsx`), not at `app/docs/`.
  Fumadocs' conventional layout plus `basePath` would produce `/docs/docs/…`.
- **The search client does not inherit `basePath`.** `RootProvider` is given
  `search={{ api: '/docs/api/search' }}` explicitly. Without it, search returns nothing
  and looks exactly like a search that works.

`robots.txt` for the domain is served by the marketing site, not here — the rewrite only
covers `/docs/*`. This app emits `/docs/sitemap.xml` and the marketing site's robots
references it. Pages set an explicit canonical on the marketing domain, and the app's own
deployment domain is `noindex`, so the two hosts do not compete for the same content.

### Edit links carry the full monorepo path

```
https://github.com/deskbellhq/deskbell/blob/main/apps/docs/content/docs/<file>
```

Docs frameworks default to assuming the content directory sits at the repository root.
In a monorepo it does not, and a wrong base produces a link that 404s on every page
without anyone noticing, because maintainers rarely click their own edit links. A test
asserts the computed URL starts with `…/blob/main/apps/docs/content/docs/`.

### Content

`apps/docs/content/docs/**` becomes the single home for user-facing documentation.
`docs/security.md` and `docs/evals.md` move there. `docs/widget-customization.md` stays
where it is, unchanged: it is generated by `scripts/gen-widget-docs.ts` and byte-compared
by `pnpm docs:widget --check`, and it serves readers working from a checkout rather than
the site. `docs/README.md` explains the split.

Pages are `.md` by default so they stay readable on GitHub, and `.mdx` only where a page
needs components.

Frontmatter is a contract, validated at build:

```yaml
title:        # page title
description:  # one standalone sentence
status:       # shipped | partial | planned — rendered as a badge
updated:      # YYYY-MM-DD — rendered as "Last updated"
```

`status` exists because parts of v1 are not built. A page describing something
unfinished says so in its first paragraph and carries the badge; `ROADMAP.md` remains the
authority for what is and is not built, and `content/docs/status.mdx` transcribes it.

### Images stay lean

`Dockerfile`'s `deps` stage copies every app and runs an unfiltered install, so a new app
puts its whole toolchain into the shipped `web` and `worker` images. The install is
filtered to the two subgraphs that actually ship:

```
pnpm install --frozen-lockfile --filter "@deskbell/web..." --filter "@deskbell/worker..."
```

The docs app is not in `docker-compose.yml` and adds no service; Postgres remains the
only infrastructure dependency.

### Keeping it true

- Tests in `apps/docs/lib` cover the frontmatter contract, internal links, the edit-link
  path, the routing constants, absolute URLs in machine-readable output, and the
  requirement that every `WIDGET_OPTIONS` key has a `WIDGET_OPTION_META` entry. They run
  in CI as part of `pnpm test`, since turbo already picks the app up. `pnpm docs:check` is
  a convenience alias for running them alone.
- A CI job fails a change to `apps/web/app/api/v1/**`,
  `packages/shared/src/widget-config*.ts`, `.env.example`, `docker-compose.yml` or
  `packages/core/src/models/**` that does not also touch `apps/docs/content/**`.
  `[skip docs]` in the pull request body overrides it.
- **Search has no automated test.** Fumadocs 16 serves it from a route handler rather
  than a build artifact, so there is no index file to assert against, and a test of the
  handler would not exercise the client-side fetch that is the part that breaks. It is
  covered by `routing.test.ts` pinning the prefixed URL, and by the manual check recorded
  below. A real guard would need an end-to-end browser test, which this repository has no
  harness for yet.

## Non-goals

- **An API reference.** `/api/v1/*` request and response shapes are not documented in this
  pass. They should eventually be generated from the zod schemas the route handlers
  already use, which is product work and gets its own spec.
- **A generated configuration table.** Environment variables are hand-written here from
  `.env.example` and the config modules. A typed manifest generating both would be
  better and is likewise product work.
- **Versioning.** One version, no switcher. The URL shape stays compatible with adding
  one.
- **Changing `scripts/gen-widget-docs.ts`.** Untouched, including its CI check.
- **Anything under `.ai/` appearing in site navigation.** `docs/` is for people running
  Deskbell; `.ai/` is for people building it.

## Open questions

1. **`docker-compose.yml` passes through only `OPENAI_API_KEY`, `DESKBELL_CHAT_MODEL` and
   `DESKBELL_EMBEDDING_MODEL`.** `ANTHROPIC_API_KEY` and `OLLAMA_BASE_URL` are not wired
   in, so the compose path cannot reach an Anthropic or Ollama model without editing the
   file. Documented as a limitation; the fix belongs in the compose file.
2. **Dark mode.** This site ships light and dark; the marketing site has light only. The
   dark palette authored here is the first one that exists. Either the marketing site
   adopts it or the two drift.
3. **Licence for `apps/docs/content/**`.** The repository default is AGPL, which is
   awkward for anyone quoting the documentation. CC-BY-4.0 alongside the existing MIT
   carve-outs would be better and needs a change to `LICENSING.md`.
4. **The widget on this site.** Embedding it requires a reachable Deskbell deployment,
   which does not exist yet. Until one does, the site ships without it.

**Two defects found and fixed during verification, both invisible to the build:**

1. **llms.txt emitted root-relative links.** The loader emits `/quickstart`
   because Next prefixes rendered links with `basePath` itself. Nothing does
   that for text written into a file, so an agent following llms.txt would have
   landed on `deskbell.dev/quickstart`, which is the marketing site, and
   reported the documentation missing rather than wrong. Machine-readable output
   is now absolute, pinned by `llms-index.test.ts`.
2. **Sidebar sections were duplicated.** Using both a separator and a folder
   title rendered "Self-hosting" twice and produced a
   "Documentation › Self-hosting › Self-hosting" breadcrumb in search results.
   Separators now group only loose files.
