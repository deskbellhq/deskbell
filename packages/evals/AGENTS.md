# @deskbell/evals

The eval harness (D8). Replays a question set against an answering system, grades the answers, and reports. AGPL: it may import `core`/`db`/`connectors`; nothing MIT (`widget-*`, `sdk`, `ui`, `shared`) may import it.

Rules:
- **Marking criteria, not golden answers.** A case declares the facts a correct answer must contain. Never add a `expectedAnswer` field — grading against one reference answer means guessing which of its parts were essential.
- **Two headline numbers, never blended.** Factuality (answerable cases) and Uncertainty (unanswerable cases) are reported separately. A system can buy either at the other's expense, and one combined score hides exactly that. The blend is easiest to reintroduce one level down, inside a judge: keep groundedness a separate judgement, and never let doubt about where a fact came from decide whether it is present.
- **A judge decides facts, not letters.** It answers one binary question per marking criterion; `gradeFromFacts` turns the answers into A/B/C. Never ask a judge to pick a grade — agreement on a scale has to be validated at every point of it, and the A/B boundary is the one no two graders draw alike. Anything a judge returns that is not one of the case's criteria is dropped and counted as an anomaly, never scored.
- **Factuality is mean fact coverage, not a mean of grades.** Averaging A/B/C asserts the A→B gap equals the B→C gap and collapses "missed one of six" onto "missed one of two". The letter survives as the per-case outcome the baseline diffs, which is the job it is good at.
- **Empty is a result; null is an absence.** `TargetAnswer.retrieved` is `null` only when the target cannot observe retrieval. A target that looked and found nothing returns `[]` and the case scores zero. Collapsing the two lets a change that starves retrieval on the hardest questions raise recall by shrinking the denominator.
- **Judge alignment never reaches the baseline.** `--labels` measures a judge against human grades; it describes a judge and a label file, not the system under test, so gating on it would make relabelling read as a regression.
- **A retrieval-only run cannot write or check a baseline.** It grades nothing, and its baseline would overwrite the quality half of the record with nulls.
- **The fixture measures drift, not quality.** Its questions are authored against a corpus we control, so its absolute scores mean nothing alone. Absolute numbers come from `--project` runs against real corpora with questions mined from real traffic. Never present fixture numbers as a quality claim.
- **Determinism is the gate's foundation.** The fixture path must not touch the network, the clock, the database, or a random source. `fixture.test.ts` asserts two runs agree; if that test goes flaky, fix the cause rather than the assertion.
- **No provider SDKs here** (root rule 8, D4/D13). The LLM judge takes injected completion access from `@deskbell/core/models`.
- **A judge never grades its own model silently.** `DESKBELL_JUDGE_MODEL` exists to point it elsewhere; when it falls back to the answering model the judge's name carries `(self-graded)` so the caveat reaches the report and the baseline. Never strip that marker to tidy a name.
- **Injection resistance is a substring check, never a judge call.** Whether a forbidden string was emitted is a fact. Do not "improve" it into an LLM call — a judge can be talked out of the verdict by the same text that did the talking.
- **Never put an injection case in the fixture set.** The stub generator has no instructions to disobey and would pass it unconditionally. Injection cases need `--real-model` (controlled corpus, real generator) and live in `datasets/injection.json`, which never gates CI.
- A baseline change is a reviewed act: re-run with `--update-baseline` and commit the baseline in the same change as whatever moved it.
- **A set built on a corpus we cannot republish goes in `datasets/private/`.** That directory, `baselines/private/` and `reports/` are gitignored, and `defaultBaselinePath` mirrors a set's subpath so its baseline follows it there without a flag. Keeping the questions back while committing the baseline publishes the answer key — the baseline names every case id — and a `--json` report carries every question verbatim alongside its marking criteria and cited document ids. (Answer text is not stored in a report — keep it that way; a report is a measurement, not a transcript.) Never widen the ignore to a per-file pattern: a new set has to inherit the rule from where it sits, not from someone remembering.
- **The gate is the fixture and only the fixture.** `pnpm evals:check` takes no `--dataset` and must not grow one. A private set cannot gate CI (nobody else can run it) and neither can a `--project` run (it needs a database, a key, and a live model, and is not reproducible run to run).
