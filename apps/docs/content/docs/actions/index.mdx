An answer from the documentation covers "how do I cancel an order". It does
not cover "where is *my* order". Actions close that gap: a project attaches
one or more [MCP](https://modelcontextprotocol.io) servers, the tools those
servers expose are discovered, and during a conversation the model may call
the ones you allowed. A result is cited like a page, and every call is
recorded.

![The widget on a page: a finished step line for a lookup above the answer, then a confirmation card for cancelling an order that lists the order id and offers Cancel and Confirm](/images/widget-confirmation.png)

Nothing runs by default. A newly discovered tool is **off** until an admin
sets it to **Allowed** (runs on its own) or **Needs confirmation** (the
visitor sees a card naming the call and decides). Deskbell suggests
*Allowed* only for tools the server itself marks read-only; anything else is
suggested as *Needs confirmation*.

## How a turn runs

1. The visitor asks. Retrieval runs as usual and the model receives the
   matching content **and** the list of allowed tools.
2. If the model calls a tool, the widget shows a step line above the answer
   (*Look up your order…*, then a check mark). The result is handed back to
   the model as material — never as instructions — and the answer continues.
3. If the tool needs confirmation, the turn pauses. The widget shows a card
   naming the tool and listing its arguments; the visitor confirms or
   cancels; the answer resumes in a new bubble.
4. The model cites the tool results it relied on the way it cites pages;
   the widget shows that as the step line rather than as a source.

A turn is bounded: four model steps by default, thirty seconds per call, and
eight thousand characters of a result shown to the model
([environment variables](/deploy/environment-variables#actions)).

## What the visitor sees

- A step line per call above the answer: the tool's label
  ([as the operator wrote it](/actions/mcp-servers#shown-to-visitors)) with a
  spinner while it runs, a check mark when it finished, *Couldn't complete*
  when it failed. The lines sit under one fold that is open while the model
  works and closes once the answer starts, with a summary such as *Worked
  for 3s · 2 steps*; the visitor can open it again. With
  [`DESKBELL_SHOW_REASONING`](/deploy/models#showing-the-reasoning) on, the
  model's reasoning appears between the lines.
- For a confirmation, a card with the tool's label, the arguments one per
  line, and *Cancel* / *Confirm*. Once answered it becomes a step line on
  the same message; it expires after ten minutes.
- Nothing under Sources: the step line is the record that live data was
  used.

Everything a tool returns may be shown to the visitor. Attach a server the
way you would give a support agent access to it.

## What you see

- **Actions**: every tool across your servers with what the visitor sees it
  called, what the model is told, its policy, and its last thirty days —
  calls, failures, median duration. Each tool has a page with its recent
  calls; the **Servers** tab holds the connections; the **Log** tab holds
  every call.
- **Conversations**: each answer lists the calls it made — tool, outcome,
  duration — and a card's verdict.
- **Actions › Log**: the [log](/actions/log) of every call across
  conversations, with its arguments, its result, who it ran for and how it
  ended; filter it, open a record, download it as CSV.
