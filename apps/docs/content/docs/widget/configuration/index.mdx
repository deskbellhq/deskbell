Four layers, each an escape hatch for the one below. Most deployments stop at
the first.

1. **Dashboard.** Set appearance under Appearance. No code, no redeploy.
2. **Attributes.** Override anything per page from the embed code.
3. **CSS.** `--deskbell-*` custom properties for colour, `::part()` for shape.
4. **Slots.** Replace the launcher, header, empty state or footer with your own
   markup.

Precedence, lowest to highest:

```
defaults  <  dashboard config  <  attributes / JS config  <  host-page CSS
```

Host-page CSS wins last on purpose. `deskbell-widget { --deskbell-accent: red }`
is the most explicit statement of intent on the page, so nothing resolved at
runtime beats it. No rule in the widget uses `!important`.

</Callout>
